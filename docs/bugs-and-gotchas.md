### 2026-10-23 — Сохранённое согласие пропускало обработчики аналитики

- Симптом: при повторном посещении не отправлялись собственные события CTA в Метрику и GA4 и не открывались настройки аналитики.
- Причина: ранний `return` после загрузки счётчиков при сохранённом согласии завершал скрипт до регистрации обработчиков.
- Решение: сохранить инициализацию счётчиков, но продолжить регистрацию обработчиков; показ баннера оставить только для отсутствующего решения.
- Проверка: `node --test scripts/test-analytics-consent.mjs`; повторное открытие настроек после перезагрузки в браузере. Исправление подготовлено локально, публикация отдельно.
- Где связано: `src/components/CookieConsent.astro`.

Добавляй только подтверждённые повторяющиеся проблемы: сборка Astro, пути импортов, переменные окружения, индексация, аналитика или публикация. Разовые черновики, логи и неподтверждённые гипотезы сюда не переносить.

### 2026-09-18 — В переменных аналитики нужны идентификаторы, а не код счётчика

- Симптом: баннер согласия показывается, но после разрешения скрипты Метрики и GA4 не подключаются.
- Причина: `PUBLIC_YANDEX_METRIKA_ID` и `PUBLIC_GA_ID` пусты или содержат полный HTML/JavaScript-код вместо одного идентификатора.
- Решение: для Метрики записать только числовой номер счётчика, для GA4 — только идентификатор вида `G-…`; значения хранить в локальном `.env` и GitHub Variables, не в Git.
- Проверка: сборка содержит заполненные `data-yandex-id` и `data-google-id`, а после согласия браузер запрашивает оба скрипта.
- Где связано: `.env`, GitHub Variables, `src/components/CookieConsent.astro`, workflows публикации.

### 2026-09-18 — Приватный репозиторий отключает GitHub Pages

- Симптом: домен начинает отдавать 404, HTTPS перестаёт работать, а API GitHub Pages возвращает 404.
- Причина: репозиторий сайта был переведён из public в private; для текущего тарифа публикация GitHub Pages была удалена вместе с привязкой домена.
- Решение: вернуть репозиторию видимость public, заново включить Pages с типом сборки `workflow`, привязать `maria-galieva.ru`, запустить deploy и после выпуска сертификата включить обязательный HTTPS.
- Проверка: workflow завершён успешно; `https://maria-galieva.ru/` отдаёт 200, `https://www.maria-galieva.ru/` перенаправляет на основной домен.
- Где связано: GitHub repository settings, `.github/workflows/deploy.yml`, DNS домена в Timeweb.

### 2026-11-26 — Production-проверка ожидает устаревшее число URL

- Исправлено локально 2026-11-26: production-скрипт проверяет точный набор из 4 утверждённых URL, запрещает дубли и лишние адреса. `npm run verify:production` полностью прошёл на основном домене; 2 корректных варианта приняты, 5 некорректных отклонены. Следующие пункты описывают исходный сбой до исправления.

- `scripts/verify-production-launch.mjs:78` ожидает 3 URL в sitemap, хотя текущий опубликованный `src/pages/sitemap.xml.ts` содержит 4, включая `/uslugi/codex-dlya-rukovoditeley/`. Поэтому общий скрипт останавливается до проверки редиректов.
- Подтверждено после выпуска карточек `c4b6868`: sitemap не менялся относительно базы `b5b1431`, отдельная проверка подтвердила точный набор из 4 URL и доступность кейсов. Не считать этот сбой регрессией карточек или успешным прохождением всей production-проверки. При обновлении проверки сверять полный набор маршрутов, а не только менять число ради зелёного результата.

### 2026-11-26 — Общие редакционные стили меняют сетку ОММТ и Tactus

- Подтверждено при разборе замечаний Марии: правила case-editorial.css для case-reviewed меняли ommt-hero-heading и карточки подготовки, вследствие чего изображение оказывалось под текстом, а номера и заголовки расходились.
- Исправление ограничено src/styles/ommt.css: собственные сетки заданы под .ommt-page .ommt и не меняют другие кейсы. Не проверять лишь значения CSS-файла — проверять итоговую геометрию в браузере после подключения общих стилей.
- Проверено на собранной странице: изображение справа при 1440 px; подготовка, роли и результаты не переполняют рамку 320 px. Служебные доказательства: .agent/tasks/ommt-layout-revision-2026-11-26/.
- Та же причина подтверждена в Tactus: общий селектор .case-reviewed main .tc-hero-grid менял сетку на 1 колонку. Исправление ограничено стилями Tactus. После каждого общего CSS-прохода проверять существующие кейсы, типографику карточек и вычисленные координаты, а не только новый файл.

### 2026-11-26 — Подгонка изображения по высоте создаёт фоновые полосы

- Симптом: в hero Tactus появились искусственные жёлтые полосы и чрезмерная обрезка экранов после попытки уравнять высоту картинки и текста.
- Причина: растянутый контейнер, фон контейнера и object-fit: contain заполняли несоответствие пропорций подложкой; object-fit: cover до этого срезал значимую область. Равенство размеров в DOM ошибочно принималось за удачную композицию.
- Решение: сохранить исходник, подобрать кадр с воздухом и расширить колонку; вывести img в естественном отношении сторон с height: auto. Не добиваться одинаковой высоты ценой полос и потери смысла.
- Проверка: на 390, 1100, 1440 px отношение сторон изображения соответствует исходнику; у контейнера нет добавленного фона, изображение просмотрено целиком. Финальные снимки Tactus: tactus-natural-hero-*.png в папке визуализаций этой задачи.
- Где связано: src/styles/tactus.css; [UI-кит](ui-kit.md#hero-и-изображения-кейсов).

### 2026-11-26 — Ссылка предпросмотра есть, сервер уже остановился

- Симптом: Мария повторно не могла открыть ранее присланную ссылку Tactus, порт не слушался.
- Причина: локальный сервер был привязан к завершившемуся запуску; существование dist и URL не означало доступность страницы.
- Решение: проверить процесс и ответ; при необходимости запускать сервер отдельным скрытым фоновым процессом. Не устанавливать новый сервер и не подменять рабочую сборку без необходимости.
- Проверка: после запуска — HTTP 200 и ожидаемый заголовок последней сборки, затем просмотр. Если используется headless-снимок, изображения ниже hero предварительно прокрутить в видимую область и дождаться декодирования: complete/naturalWidth не гарантируют готовую отрисовку на снимке.
- Где связано: [разбор Tactus](cases/tactus-lessons-2026-11-26.md), проверки предпросмотра и изображений.

### 2026-11-26 — Сравнение рабочей папки с публикацией

* Рабочая ветка отстаёт от отдельных согласованных выпусков main. Git status относительно HEAD ошибочно выглядит как список неопубликованного; часть новых файлов уже есть в main.
* Сравнивать файлы с актуальной main, включая неотслеживаемые относительно старого HEAD. Нормализовать CRLF только у текста: преобразование бинарных файлов даёт ложные расхождения.
* Для следующего выпуска брать проверки из main. Сохранить устаревшие локальные скрипты поверх main означает потерять проверки Banana Traders и других опубликованных функций.
