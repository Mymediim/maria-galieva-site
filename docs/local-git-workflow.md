# Локальная работа с Git

Git сохраняет историю изменений проекта на этом компьютере. GitHub подключён отдельно: он нужен для резервной копии, совместной работы, pull request и автоматизаций. Отправка изменений в GitHub (`git push`) выполняется только по прямому запросу Марии.

## Базовый цикл

1. Посмотреть состояние: `git status --short --branch`.
2. Посмотреть изменения до commit: `git diff`.
3. Проверить, что среди файлов нет `.env`, credentials, ключей, баз данных, резервных копий и временных артефактов.
4. Показать Марии список файлов для сохранения.
5. После согласования добавить только проверенные файлы и создать commit с коротким описанием.

История последних сохранений: `git log --oneline --max-count=10`.

## Русский словарь

- «Сохрани точку», «зафиксируй изменения», «сделай снимок проекта» — проверить состояние и безопасность списка файлов, затем создать локальный commit. Не выполнять push.
- «Что изменилось?», «покажи изменения», «покажи diff» — показать статус и diff, кратко объяснить результат.
- «Покажи историю», «какие были сохранения», «какие были commit» — показать последние десять commit.
- «Откати последний файл», «верни файл как было», «отмени изменения в файле» — сначала показать изменения, которые будут потеряны, и запросить подтверждение для одного конкретного файла.

## Правила безопасности

- Не добавлять в Git секреты, токены, `.env`, credentials-файлы, приватные ключи, базы данных и резервные копии.
- Не делать массовый откат и не выполнять push без явного подтверждения Марии.
- Если секрет попал в файл или историю Git, прекратить его использовать, заменить и отдельно проверить историю.
